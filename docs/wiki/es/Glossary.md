## Glosario

| Término | En sencillo | Con precisión | Dónde se explica |
|---|---|---|---|
| YARA | Una forma de escribir «busca estas palabras o estos bytes dentro de un archivo» para que lo haga un ordenador. | Un lenguaje para describir patrones de archivos más un programa que los busca; su documentación lo presenta como una herramienta pensada para (pero no limitada a) ayudar a investigadores de malware a identificar y clasificar muestras. | [Tecnología: YARA](ES-Tech-YARA) |
| Regla | Un cartel de «se busca»: un archivo con esta frase y este tamaño merece una segunda mirada. | Una regla YARA dentro de un archivo `.yar`/`.yara`; el canal clasifica cada archivo de reglas como aceptado, en cuarentena o rechazado, con motivos. Una coincidencia no prueba peligro. | [Canal YARA](ES-YARA-Channel) |
| YARA-X | Un motor más nuevo para el mismo lenguaje. | La reencarnación de YARA de VirusTotal, escrita en Rust. En este proyecto `VirusTotal/yara-x` es una entrada de tipo `engine` en `config/sources.json`; no aporta reglas y no se usa para validar. | [Tecnología: YARA](ES-Tech-YARA) |
| Fuente de reglas | El sitio de donde se recogen las reglas; el canal no escribe ninguna. | Uno de dos repositorios públicos, `Neo23x0/signature-base` y `Yara-Rules/rules`; cada publicación registra repositorio, commit y resultado de la comprobación de licencia. Las reglas de terceros conservan su propia licencia; el proyecto no reclama derechos de autor sobre ellas. | [Fuentes](ES-YARA-Sources) |
| Hash | Una huella de un archivo: si cambias una letra, la huella cambia por completo. | Un resumen SHA-256; el manifiesto firmado lista el SHA-256 de cada archivo de una publicación. | [Verificar una publicación](ES-YARA-Verify) |
| Firma digital | Un sello que dice quién envió algo y si cambió por el camino. | Una firma criptográfica comprobada contra una identidad; muestra la identidad de quien firma y la integridad de los bytes firmados, no quién escribió el contenido ni que sea bueno. | [Tecnología: Sigstore](ES-Tech-Sigstore) |
| Sigstore | Un servicio público que da a quien firma un sello válido unos minutos y guarda un registro público de su uso. | Un proyecto abierto de firma (autoridad de certificados Fulcio, registro de transparencia Rekor, cliente `cosign`) usado aquí para comprobar que `publish.yml` firmó una publicación. | [Tecnología: Sigstore](ES-Tech-Sigstore) |
| Firma sin clave (keyless) | Firmar sin dejar una clave secreta guardada por ahí. | El par de claves es efímero y se descarta tras firmar; GitHub emite un token OIDC que nombra el flujo de trabajo y Fulcio lo une a un certificado de vida corta; la verificación se apoya en el registro y comprueba identidad y emisor. | [Tecnología: Sigstore](ES-Tech-Sigstore) |
| Manifiesto | El albarán: la lista de todo lo que lleva un paquete. | `manifest.json`, firmado con Sigstore, con el SHA-256 de cada archivo más `sources`, `rules_root` y el tamaño y la raíz del registro. | [Publicación y firma](ES-YARA-Publishing) |
| Bundle (paquete) | Un paquete. La palabra tiene dos sentidos en esta wiki. | (1) El paquete de reglas `rules-release.tar.gz`. (2) El archivo `.sigstore.json` que guarda una firma, su certificado y el apunte del registro, usado por `cosign verify-blob --bundle`. | [Publicación y firma](ES-YARA-Publishing) |
| Publicación (release) | Una entrega completa de todas las reglas aprobadas. | Un paquete completo de reglas con su manifiesto, su punto de control y los bundles de firma, publicado por `publish.yml`. | [Publicación y firma](ES-YARA-Publishing) |
| Registro de transparencia | Un diario donde solo se añaden líneas, nunca se cambian ni se borran. | Un registro público de solo añadir (`logs/log.jsonl`, una hoja por línea) cuyo crecimiento se verifica con pruebas de Merkle. | [Registro de transparencia](ES-YARA-Transparency) |
| Punto de control | Una foto firmada del diario en un momento. | `checkpoint.txt`: tres líneas con origen, número de entradas y raíz, firmadas con Sigstore; el manifiesto repite el mismo tamaño y la misma raíz. | [Registro de transparencia](ES-YARA-Transparency) |
| Árbol de Merkle | Una forma de apretar una lista larga en un número que cambia si algo de la lista cambia. | Un árbol de hashes (construcción de la RFC 6962): hoja = SHA-256(`0x00` + datos), nodo = SHA-256(`0x01` + izquierda + derecha); implementado en `scripts/tlog.py`. | [Tecnología: Merkle](ES-Tech-Merkle) |
| rules_root | El número único que representa el conjunto exacto de archivos de reglas. | La raíz de Merkle cuyas hojas son la ruta más el hash de cada archivo de reglas, ordenadas por ruta. | [Tecnología: Merkle](ES-Tech-Merkle) |
| Prueba de inclusión | Una prueba corta de que un elemento está de verdad en la lista. | Un camino de hashes, del orden de log2(n) entradas, que reconstruye la raíz firmada desde una hoja. | [Tecnología: Merkle](ES-Tech-Merkle) |
| Prueba de consistencia | Una prueba corta de que la lista de hoy solo añadió cosas a la de ayer. | Un conjunto de hashes que muestra que un árbol antiguo es un prefijo de uno más nuevo, así que la historia no se reescribió. | [Tecnología: Merkle](ES-Tech-Merkle) |
| Cuarentena | Una sala de espera para las reglas que no pasaron las comprobaciones. | Archivos de reglas que no se publican: rechazados, bloqueados o pendientes de revisión; un revisor solo puede aprobar o rechazar los pendientes y el archivo se valida de nuevo después. | [Cuarentena de reglas](ES-YARA-Quarantine) |
| Panel de revisión | La pantalla donde una persona decide sobre las reglas en cuarentena. | Un servicio privado de revisión; los roles limitan lo que cada persona puede decidir y cada decisión se escribe en un registro encadenado por hashes. | [Cuarentena de reglas](ES-YARA-Quarantine) |
| Falso positivo / falso negativo | La alarma suena por algo inocente, o calla ante algo malo. | Una regla que coincide con un archivo benigno, o una que no detecta un archivo malicioso. El canal mide y filtra pero no puede prometer que no haya ninguno de los dos. | [Límites](ES-YARA-Limits) |
| S3 y bucket | Una forma habitual de hablar con el almacenamiento en la nube, donde los archivos viven en «cubos». | La API de objetos compatible con S3 que implementan muchos proveedores; el archivo previsto usa un bucket por proveedor. | [Tecnología: S3 y copias](ES-Tech-S3-Backups) |
| Versionado | Guardar copias antiguas en vez de sobrescribirlas. | Una función del bucket que conserva versiones anteriores de un objeto; es requisito de Object Lock. | [Tecnología: S3 y copias](ES-Tech-S3-Backups) |
| Object Lock | Un candado que impide borrar o reemplazar un archivo guardado durante un tiempo fijado. | Una función de retención que impide borrar o sobrescribir una versión durante un periodo de retención, en modo governance o compliance. | [Tecnología: S3 y copias](ES-Tech-S3-Backups) |
| Modo governance | Un candado que aún puede abrir quien tenga la llave maestra. | Modo de Object Lock en el que una identidad con el permiso adecuado puede saltarse el bloqueo; no frena a una identidad autorizada que esté comprometida. | [Archivo histórico](ES-YARA-Archive) |
| Modo compliance | Un candado que nadie puede abrir hasta que pase el tiempo. | Modo de Object Lock que nadie puede quitar durante la retención; es irreversible, así que un error de subida no se podría retirar. No está activado en este proyecto. | [Archivo histórico](ES-YARA-Archive) |
| Archivo histórico | Una copia extra prevista de cada publicación en tres sitios. | Un archivo en tres proveedores con versionado y Object Lock. Está planificado: no es operativo y no se ha probado ninguna restauración real. | [Archivo histórico](ES-YARA-Archive) |
| Firma de código | El desarrollador pone un sello a su app. | Una firma sobre la app que dice quién la firmó y permite a macOS saber si cambió después. | [Tecnología: firma de código](ES-Tech-CodeSigning) |
| Notarización | Apple pasa una comprobación automática a la app y devuelve un resguardo. | Una comprobación automática de Apple (`xcrun notarytool`) cuyo resguardo se grapa a la app; no es garantía de que no haya malware. | [Tecnología: firma de código](ES-Tech-CodeSigning) |
| Gatekeeper | El portero de macOS que mira el sello y el resguardo de las apps descargadas. | El componente de macOS que, al abrir algo descargado, comprueba la firma y la notarización y pide tu aprobación. | [Tecnología: firma de código](ES-Tech-CodeSigning) |
| Entitlement (permiso especial) | Un permiso especial que Apple da a un desarrollador para poderes delicados. | Una capacidad restringida concedida a una cuenta de desarrollador, necesaria por ejemplo para Endpoint Security y Network Extension. | [Tecnología: Network Extension](ES-Tech-NetworkExtension) |
| Endpoint Security | Un guardia al que el sistema pregunta «¿lo dejo pasar?». | Un framework de Apple que entrega eventos de aviso y de autorización (AUTH) sobre lo que ocurre en el sistema; los AUTH deben responderse permitir o denegar dentro de un plazo. | [Tecnología: Endpoint Security](ES-Tech-EndpointSecurity) |
| Network Extension | El puesto de guardia que deja a un programa vigilar y controlar el tráfico de red de otras apps. | El framework de Apple para filtrar conexiones, hacer de proxy DNS o crear una VPN; necesita un entitlement. | [Tecnología: Network Extension](ES-Tech-NetworkExtension) |
| DriverKit | Una forma de escribir controladores de hardware que no corren en el núcleo del sistema. | El framework de Apple para controladores que corren fuera del kernel como programas separados, así que un controlador que falla no tumba el Mac. | [Tecnología: DriverKit](ES-Tech-DriverKit) |

## Límites

La columna sencilla simplifica a propósito y nunca promete detectarlo todo. Los términos de los frameworks de Apple describen lo que dicen las páginas de esta wiki, no cada detalle de la documentación de Apple. Los estados (operativo, planificado) viven en las páginas enlazadas y en la matriz de evidencias, no aquí.
